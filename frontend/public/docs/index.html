[ 01 / OVERVIEW ]

What FRAME Does

Relationship Graph

Connects customers, cards, devices, IP addresses, and merchants so shared infrastructure becomes visible.

Temporal Context

Tracks short-window activity such as device bursts, IP bursts, unique customers, and merchant reuse.

Risk Scoring

Scores incoming transactions using graph-derived and temporal features with a calibrated online model.

Analyst Evidence

Surfaces observed network facts for investigation without pretending they are model feature attributions.

[ 02 / ARCHITECTURE ]

Signal to Decision

Incoming transaction
        ↓
Graph context + 30-minute temporal state
        ↓
13-feature online vector
        ↓
Calibrated risk model
        ↓
ALLOW / REVIEW / BLOCK policy
        ↓
Observed network evidence
        ↓
FastAPI + analyst dashboard

FRAME keeps the decision policy deterministic. The model produces a risk score; the policy converts that score into an operational action.

[ 03 / RISK ENGINE ]

Policy

Risk scoreAction
< 0.020ALLOW
0.020 – 0.699REVIEW
>= 0.700BLOCK
Important: observed evidence is context for analysts. It is not a claim that any single signal caused the model score.

Synthetic graph benchmark

On the locked hard-negative synthetic benchmark, 95.83% of planted fraud is intercepted through REVIEW or BLOCK, and all 3 / 3 planted coordinated rings produce graph-backed evidence.

The real ULB experiment validates transaction-level discrimination only. It does not validate customer/device/IP graph-ring detection because those relationship identifiers are not present in the dataset.

[ 07 / SCOPE & LIMITS ]

Prototype Boundaries

  • Online graph and temporal state are currently held in memory.
  • Server restarts reset runtime state.
  • The public prototype does not include production authentication or authorization.
  • FRAME is not presented as a production-ready fraud engine.
  • No LLM independently authorizes or blocks a transaction.
