[ 01 / OVERVIEW ]

What FRAME Does

Relationship Graph +

Connects customers, cards, devices, IP addresses, and merchants so shared infrastructure becomes visible.

FRAME builds an undirected payment-relationship graph and uses local graph context such as entity degree and connected-component size during online scoring.

Temporal Context +

Tracks short-window activity such as device bursts, IP bursts, unique customers, and merchant reuse.

The online feature schema uses a rolling 30-minute window to capture coordination invisible in lifetime aggregates.

Risk Scoring +

Scores incoming transactions using graph-derived and temporal features with a calibrated online model.

The model outputs a score; the operational ALLOW / REVIEW / BLOCK policy remains deterministic.

Analyst Evidence +

Surfaces observed network facts without pretending they are model feature attributions.

Evidence includes shared infrastructure, bursts, multi-customer reuse, multi-merchant device reuse, and large components.

Signal to Decision

02Graph context
0330-minute state
0413-feature vector

FRAME keeps the decision policy deterministic. The model produces a risk score; policy converts that score into an operational action.

[ 03 / RISK ENGINE ]

Policy

Risk score < 0.020ALLOW
0.020 – 0.699REVIEW
Risk score ≥ 0.700BLOCK
Important: observed evidence is context for analysts. It is not a claim that any single signal caused the model score.

GET/api/v1/graph+

Current payment relationship graph snapshot.

GET/api/v1/risk/recent+

Recent risk decisions with a bounded optional limit.

GET/api/v1/risk/{transaction_id}+

Investigation detail for one transaction.

POST/api/v1/risk/score+

Scores a transaction, applies policy, records evidence, and updates graph/temporal state.

Synthetic graph benchmark

On the locked hard-negative synthetic benchmark, 95.83% of planted fraud is intercepted through REVIEW or BLOCK, and all 3 / 3 planted coordinated rings produce graph-backed evidence.

The real ULB experiment validates transaction-level fraud discrimination only. It cannot validate FRAME's customer/device/IP graph-ring layer because those identifiers are absent from the public dataset.

[ 07 / SCOPE & LIMITS ]

Prototype Boundaries

In-memory state +

Runtime graph and temporal state reset when the backend restarts.

Production deployment would require persistent shared state.

Single-process state +

The current state model is intended for a single service process.

Multiple workers require an external state or graph store.

No production fraud claim +

Synthetic graph results remain explicitly synthetic.

Real-data results support transaction-level discrimination claims only.

No LLM authorization +

The scoring path does not depend on a language model.

Any future LLM component would summarize already-computed evidence and would not independently authorize or block a transaction.
